# Zach Jacob — portfolio

A modern neumorphic portfolio with a tap-to-change 3D ribbon, six empty project spaces, and a folded interactive CV. No earlier conversation projects or portrait photos are included.

## Publish with GitHub and Netlify

1. Create a **private** GitHub repository named `zach-jacob-portfolio`.
2. Add the contents of this folder at the repository root. Include `app`, `lib`, `public`, `scripts`, `package.json`, `package-lock.json`, `tsconfig.json`, `next.config.ts`, `netlify.toml`, `.gitignore`, and `.nvmrc`. Never upload `node_modules`, `.next`, `.local-data`, or `.env.local`.
3. In Netlify, choose **Add new project → Import an existing project → GitHub**, and select this repository. Use the Free plan.
4. The supplied configuration sets the build command to `npm run build`, the publish directory to `.next`, and Node.js to 22. Netlify detects Next.js and installs its framework adapter automatically. Use a repository import, not Netlify Drop: the editable features need server functions.
5. Before publishing, set a private environment variable named `OWNER_PASSWORD` in Netlify's project configuration. Choose a unique random password of at least 16 characters, preferably generated by your password manager. Keep it out of GitHub, source files, and chat messages. Give it the Functions runtime scope if scope selection is available. The login fails closed until this is set.
6. Deploy the project. Choose an available project name in Netlify to get an address like `chosen-name.netlify.app`. No purchased domain is required.
7. Open `/owner` on the new address and sign in. The gallery displays **+ Add project** and private edit controls. The CV section displays **Edit my CV** and **Replace PDF**. Use **Sign out** in the footer when finished.

Netlify's free usage limits apply. Do not enable paid upgrades for this portfolio unless you decide to later.

## Editing

Project titles, categories, descriptions, links and abstract covers are saved in Netlify Blobs. CV text and replacement PDFs also persist across deployments and devices. The web CV and downloadable PDF are separate: edit the text through the CV editor, and replace the PDF separately. PDF uploads are limited to 4 MB to stay under server request limits.

Owner login uses a signed, HttpOnly, SameSite cookie with an 8-hour expiry. Changing `OWNER_PASSWORD` and redeploying invalidates existing sessions. Login attempts are limited to 10 per 10-minute window per originating IP. Other visitors cannot write by supplying identity headers. Server writes require a valid owner session and a matching Origin. Conflicting CV/project saves are rejected using revision checks and conditional blob writes.

Deploy Previews use a separate `portfolio-preview` blob store. Production uses the `portfolio` store. Avoid setting the production password in untrusted branch/PR previews.

## Local development

Install Node.js 22 or newer, then run `npm ci`. Copy `.env.example` to `.env.local` and enter a separate local test password. Run `npm run dev` and open the printed local address. Local development stores disposable data in `.local-data`; it never acts as a production fallback. Netlify production requires its native Blobs context.

Run `npm test` for security checks, `npm run check` for TypeScript, and `npm run build` for a production build.

## Included content

The supplied CV and six placeholders were checked against the existing portfolio during migration. The original PDF is at `public/cv/pramod-zach-jacob.pdf`. Your existing hosted portfolio is a separate deployment; preparing or publishing this project does not remove it.
